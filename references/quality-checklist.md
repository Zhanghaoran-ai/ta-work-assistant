# 产出质量校验清单

本文件定义TA工作助手产出内容的质量校验标准，确保每次输出都符合质量要求。

---

## 一、校验总原则

1. **P0 零容忍**：P0 项不通过，绝对不能输出
2. **先校验再输出**：所有产出必须先过校验，再给用户
3. **自动校验为主**：能自动检查的就自动检查，减少人工
4. **问题可追溯**：校验不通过要说明哪里有问题、怎么改

---

## 二、P0 必检项（不通过不能输出）

### 2.1 链接完整性校验

| 检查项 | 校验标准 | 检查方法 |
|--------|----------|----------|
| 待办任务都有链接 | 所有可执行任务必须带飞书招聘直达链接 | 自动检查：每条待办是否有url |
| 链接格式正确 | URL格式合法，域名正确 | 正则校验：`https://hire\.(feishu|larksuite)\.cn/.*` |
| 链接文案清晰 | 链接文字说明点进去能做什么 | 关键词检查：包含"去评估"、"写评估"、"查看详情"等 |
| 高优任务链接醒目 | 优先级高的任务链接更突出 | 检查是否有emoji或加粗 |

**校验失败处理**：
- 缺链接 → 自动补上再输出
- 链接格式错 → 修正格式
- 文案不清晰 → 改成标准文案

---

### 2.2 关键信息准确性校验

| 检查项 | 校验标准 | 检查方法 |
|--------|----------|----------|
| 候选人姓名正确 | 与API返回一致，无错字 | 与原始数据比对 |
| 岗位名称正确 | 与API返回一致，无错字 | 与原始数据比对 |
| 时间计算准确 | 超时时长、面试时间等计算正确 | 重新计算验证 |
| 数量统计准确 | 总数、分类数统计正确 | 重新计数验证 |

**校验失败处理**：
- 数据不一致 → 以API返回为准，修正后输出
- 计算错误 → 重新计算

---

### 2.3 数据真实性校验

| 检查项 | 校验标准 | 检查方法 |
|--------|----------|----------|
| 不编造数据 | 所有数据都有来源，不能瞎编 | 抽查：关键数据都能对应到API返回 |
| 不虚构候选人 | 候选人必须真实存在 | 与talent_id对应 |
| 不夸大功能 | 不承诺做不到的事 | 检查是否有超出能力边界的表述 |

**校验失败处理**：
- 编造数据 → 严重问题，必须删除或修正
- 功能夸大 → 修正表述，说明能力边界

---

### 2.4 安全合规校验

| 检查项 | 校验标准 | 检查方法 |
|--------|----------|----------|
| 不泄露敏感信息 | 不输出token、密钥等 | 关键词检查：app_secret、token等 |
| 不暴露内部细节 | 不输出堆栈、内部错误码 | 检查错误信息格式 |
| 符合隐私规范 | 候选人敏感信息适度展示 | 手机号、身份证等脱敏 |

**校验失败处理**：
- 敏感信息泄露 → 立即删除，脱敏处理
- 内部细节暴露 → 改成友好的用户提示

---

## 三、P1 应检项（尽量做到）

### 3.1 格式规范性校验

| 检查项 | 校验标准 | 检查方法 |
|--------|----------|----------|
| 符合对应模板 | 输出结构与模板一致 | 与output-templates.md比对 |
| 结构清晰 | 有标题、有分段、有层次 | 结构检查 |
| emoji使用规范 | 同类场景用相同emoji | 一致性检查 |
| 术语统一 | 同一概念用词一致 | 关键词一致性检查 |

**常见问题**：
- 有时说"待评估"，有时说"简历评估" → 统一用"待评估简历"
- 有时说"候选人"，有时说"人才" → 统一用"候选人"
- emoji混用 → 按模板规范来

---

### 3.2 逻辑合理性校验

| 检查项 | 校验标准 | 检查方法 |
|--------|----------|----------|
| 优先级排序合理 | 高优的排在前面 | 检查排序逻辑是否符合规则 |
| 超时分级正确 | 3天黄、7天红，分级正确 | 重新计算验证 |
| 匹配度有依据 | 评分不是瞎给，有维度支撑 | 检查是否有各维度的打分 |
| 建议具体可执行 | 不是空话，用户知道怎么做 | 检查建议的可操作性 |

---

### 3.3 信息完整性校验

| 检查项 | 校验标准 | 检查方法 |
|--------|----------|----------|
| 核心字段不缺 | 每个候选人至少有：姓名、岗位、核心标签 | 必填字段检查 |
| 关键信息不遗漏 | 该有的信息都有 | 与模板比对，检查缺项 |
| 有总结有细节 | 既有概览，又有细节 | 结构检查 |

---

## 六、校验流程

### 6.1 自动校验（输出前必做）

```
产出内容 → P0校验 → 通过？→ 输出
                ↓ 不通过
              自动修正 → 再校验 → 通过？→ 输出
                                      ↓ 不通过
                                    人工检查
```

### 6.2 人工抽检（定期做）

- 每天随机抽检 3-5 次输出
- 按校验清单逐项检查
- 记录问题，持续优化

### 6.3 回归校验（迭代后必做）

每次功能迭代后，跑一遍测试用例：
1. 正常场景：待办列表、初筛、面试准备、报表
2. 异常场景：空数据、权限不足、网络错误
3. 边界场景：1条数据、100条数据、刚好超时

## 八、质量指标

### 核心指标

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 链接覆盖率 | 100% | 可执行任务带链接的比例 |
| 关键信息准确率 | 100% | 姓名、岗位、时间等关键信息正确率 |
| P0问题数 | 0 | 严重问题数量 |
| 用户满意度 | ≥ 4.5/5 | 用户反馈评分 |

### 观测指标

| 指标 | 说明 |
|------|------|
| 平均响应时间 | 从提问到出结果的时长 |
| 重试率 | API调用需要重试的比例 |
| 错误率 | 出现错误的比例 |
| 功能使用率 | 各功能模块的使用频次 |

## 九、问题分级与处理

### 问题分级

| 级别 | 定义 | 响应时间 | 处理方式 |
|------|------|----------|----------|
| P0 | 完全用不了，数据错误 | 立即 | 停止输出，修复后再用 |
| P1 | 部分功能受影响，体验差 | 当天 | 尽快修复 |
| P2 | 小问题，不影响使用 | 本周 | 排期优化 |

### 常见问题处理

| 问题 | 级别 | 处理方法 |
|------|------|----------|
| 链接漏了 | P0 | 自动补上，重新校验 |
| 数据算错了 | P0 | 重新计算，修正输出 |
| 格式不统一 | P1 | 调整模板，统一规范 |
| 建议太空泛 | P1 | 优化prompt，更具体 |
| 排版不好看 | P2 | 优化格式，调整间距 |

---

## 十、持续改进机制

1. **问题记录**：每次发现质量问题都记录下来
2. **根因分析**：为什么会出这个问题？是prompt的问题还是数据的问题？
3. **规则沉淀**：把修复方法加到校验清单里，下次自动检查
4. **定期复盘**：每周看一次质量数据，持续优化

> 质量不是一次性的，是持续迭代出来的。每次发现问题，都是提升的机会。
