# 异常处理与错误提示规范

本文件定义TA工作助手的异常场景处理策略和错误提示规范，确保用户遇到问题时能得到清晰、友好、有解决方案的提示。

---

## 一、错误输出统一格式

所有错误提示必须遵循以下格式：

```
⚠️ 【错误类型】问题描述
💡 建议：具体的解决方法
🔗 相关链接（可选，帮助文档/配置页面等）
```

**设计原则**：
1. 先说清楚是什么问题
2. 再告诉用户怎么解决
3. 能给链接就给链接
4. 语气友好，不甩锅，不说"系统错误"这种没用的话

## 二、认证与权限类异常

### 2.1 Token 过期

**触发条件**：API返回 token 过期错误（错误码 99991668）

**处理策略**：
1. 自动尝试刷新 token
2. 刷新成功则继续，不打扰用户
3. 刷新失败则提示用户重新授权

**用户提示**：
```
⚠️ 【登录过期】你的飞书招聘授权已过期，需要重新授权才能继续使用
💡 建议：点击下方链接重新授权一下，10秒钟搞定
🔗 [重新授权](https://open.feishu.cn/...)
```

---

### 2.2 Token 无效

**触发条件**：token 格式错误或已被撤销（错误码 99991661）

**处理策略**：直接提示重新授权

**用户提示**：
```
⚠️ 【授权失效】飞书招聘的授权信息无效了
💡 建议：需要重新授权一下，请点击链接重新登录
🔗 [重新授权](https://open.feishu.cn/...)
```

---

### 2.3 权限不足（缺少 scope）

**触发条件**：API返回权限不足（错误码 99991663）

**处理策略**：
1. 识别缺少哪个 scope
2. 告诉用户需要什么权限
3. 告诉管理员怎么开

**用户提示**（缺少投递读取权限示例）：
```
⚠️ 【权限不足】应用缺少「招聘投递读取」权限，无法获取简历数据
💡 建议：请联系飞书管理员，在开放平台为应用开启 `hire:application:readonly` 权限
🔗 [权限配置指引](references/quick-start.md#13-申请权限)

📋 还需要这些权限才能完整使用：
   ✅ hire:job:readonly - 职位读取
   ❌ hire:application:readonly - 投递读取（缺少）
   ✅ hire:interview:readonly - 面试读取
   ✅ hire:talent:readonly - 人才读取
```

---

### 2.4 未配置应用凭证

**触发条件**：用户还没配置 App ID / App Secret

**处理策略**：引导用户配置

**用户提示**：
```
⚠️ 【未配置】还没配置飞书应用信息，需要先配置一下才能用
💡 建议：告诉我你的 App ID 和 App Secret，我来帮你配置
   （或者参考快速上手指南，3分钟就能搞定）
🔗 [快速上手指南](references/quick-start.md)

📝 你可以直接说：
   "配置一下，我的App ID是cli_xxx，App Secret是xxx"
```

## 三、API 调用类异常

### 3.1 网络错误 / 连接失败

**触发条件**：网络超时、连接失败、DNS 解析失败等

**处理策略**：
1. 自动重试 2 次（间隔 1s、2s 指数退避）
2. 重试成功则继续，用户无感知
3. 重试失败才提示用户

**用户提示**：
```
⚠️ 【网络异常】暂时连不上飞书招聘服务器
💡 建议：
   1. 检查一下网络连接是否正常
   2. 稍等一会儿再试试
   3. 如果持续出现，请联系管理员

⏳ 我已经自动重试了2次，还是不行，你稍后再试试吧～
```

---

### 3.2 接口限流

**触发条件**：API 返回限流错误（错误码 99991400）

**处理策略**：
1. 自动退避重试（等待 1s、3s、5s）
2. 重试成功则继续
3. 重试失败提示用户稍后再试

**用户提示**：
```
⏳ 【请求太频繁】飞书API限流了，请求太快啦
💡 建议：稍等几秒钟再试，我已经帮你自动排队了
   （一般等个5-10秒就好）
```

---

### 3.3 系统错误（5xx）

**触发条件**：飞书服务端返回 5xx 错误

**处理策略**：
1. 自动重试 1 次
2. 失败则提示用户

**用户提示**：
```
⚠️ 【服务异常】飞书招聘服务器暂时出了点问题
💡 建议：这是飞书那边的问题，稍等一会儿再试试吧
   如果持续很久，可以去飞书状态页看看是不是服务故障
```

---

### 3.4 参数错误

**触发条件**：请求参数格式不对、缺少必填参数等（错误码 99991001）

**处理策略**：
1. 记录错误日志（开发用）
2. 友好提示用户，不要暴露技术细节
3. 给出正确的用法示例

**用户提示**：
```
⚠️ 【参数错误】查询参数有问题，拉不到数据
💡 建议：你可以换个方式问我，比如：
   • "看看今天有什么待办"
   • "帮我筛一下前端的简历"
   • "这个月的工作量怎么样"

如果问题持续出现，请联系管理员排查。
```

## 四、数据类异常

### 4.1 数据为空（暂无待办）

**触发条件**：API返回空列表

**处理策略**：友好提示，不要说"错误"，要说"太棒了"

**用户提示**：
```
🎉 【暂无待办】太棒了！你目前没有待处理的任务
💡 建议：可以摸鱼了～或者看看这些：
   • 看看这个月的工作成果："月度报表"
   • 整理一下面试题库："看看我的面试题库"
   • 检查一下有没有漏掉的："看看历史任务"
```

---

### 4.2 候选人不存在 / 已删除

**触发条件**：查询单个候选人时返回不存在

**处理策略**：
1. 单个查询：直接提示不存在
2. 列表查询：跳过这一项，继续处理其他的，最后汇总说明跳过了几个

**用户提示**（单个）：
```
ℹ️ 【候选人不存在】这个候选人的信息找不到了
💡 建议：可能已经被删除或者流转到其他岗位了
   你可以看看最新的待办列表确认一下
```

**用户提示**（列表中部分失败）：
```
📝 共找到 10 份简历，其中 1 份信息获取失败已跳过
（失败的可能是已删除或权限变更，不影响其他的）
```

---

### 4.3 数据不完整

**触发条件**：部分字段缺失，比如简历没解析、缺少联系方式等

**处理策略**：
1. 有什么数据就显示什么
2. 缺失的字段标注"暂无"
3. 不要因为缺字段就整个报错

**用户提示**：
```
ℹ️ 这份简历的部分信息还在解析中，暂时显示不完整
   主要信息已经有了，不影响初筛判断，稍后会自动补全
```

---

### 4.4 时间范围无数据

**触发条件**：用户查某个时间段的数据，但那段时间没有

**用户提示**：
```
ℹ️ 2026年7月没有找到面试记录
💡 建议：要不要看看其他时间段的？
   • 看看这个月："这个月的面试"
   • 看看上个月："上个月的工作量"
   • 看看全部："所有历史数据"
```

## 五、业务边界类异常

### 5.1 超出个人权限范围

**触发条件**：用户想看其他人的、团队的、全公司的数据

**处理策略**：说明能力边界，给出替代方案

**用户提示**：
```
ℹ️ 【权限说明】我只能看你个人的待办数据哦
💡 原因：为了数据安全，用你的身份授权，就只能看你有权限的数据

如果需要看团队数据，有两个方案：
   1. 让管理员用应用身份模式配置，可以看团队范围的数据
   2. 用飞书招聘自带的报表功能，那里有团队级统计
```

---

### 5.2 功能暂不支持

**触发条件**：用户要求的功能还没做

**处理策略**：诚实说明，记录需求，不要瞎承诺

**用户提示**：
```
ℹ️ 这个功能目前还不支持哦
💡 现在支持的功能有：
   ✅ 待办清单和超时预警
   ✅ 简历初筛和对比
   ✅ 面试准备和纪要
   ✅ 工作量统计和报表
   ✅ 数据沉淀和经验积累

你说的这个功能我记下来了，后续版本会考虑加上～
   （或者你可以先用飞书招聘系统里的XX功能）
```

---

### 5.3 数量过多，分批处理

**触发条件**：待办数量特别多（比如超过50份简历）

**处理策略**：
1. 先显示TOP 20，按优先级排序
2. 告诉用户总共有多少
3. 问要不要看更多，或者分批处理

**用户提示**：
```
📝 你有 86 份待评估简历，有点多哦
💡 我先给你看优先级最高的 20 份，剩下的可以分批处理

🔥 建议先处理这些：
   1. 急招岗位的 12 份
   2. 已经超时的 8 份
   3. 内推的 5 份

要看全部吗？还是先处理这20份？
```

## 七、异常处理总原则

### 7.1 用户体验原则

1. **不甩锅**：不说"系统错误"、"接口异常"这种用户听不懂的话
2. **给方案**：每个错误都要有解决建议，不能只说"错了"
3. **不吓唬人**：小问题用 ℹ️ 或 ⏳，严重的才用 ⚠️
4. **能重试就重试**：网络问题、限流等自动重试，用户无感知最好
5. **部分失败不影响整体**：列表里个别项失败，跳过就行，不要整个报错

### 7.2 技术原则

1. **失败可观测**：所有异常都要记日志，方便排查
2. **错误分级**：P0（完全用不了）、P1（部分功能受影响）、P2（体验问题）
3. **自动恢复**：能自动恢复的就自动恢复，不要打扰用户
4. **优雅降级**：某个功能挂了，其他功能还能用

### 7.3 安全原则

1. **不暴露敏感信息**：错误提示里不要出现 token、密钥等
2. **不泄露内部细节**：不要把堆栈、内部错误码直接给用户看
3. **统一出口**：所有错误都经过格式化，保持风格一致

## 八、异常分级与响应

| 级别 | 定义 | 示例 | 用户感知 | 处理方式 |
|------|------|------|----------|----------|
| P0 | 核心功能完全不可用 | 认证失败、网络全挂 | ⚠️ 明确提示 | 立即提示，给解决方案 |
| P1 | 部分功能受影响 | 某个接口挂了，其他能用 | ℹ️ 说明情况 | 降级处理，能用的继续用 |
| P2 | 体验问题，不影响使用 | 数据不全、格式小问题 | 可能感知不到 | 记录日志，后续优化 |

## 十、多系统特有异常处理
### 10.1 各系统认证特有异常
#### 北森 Token 过期（2小时有效期）
**触发条件**：北森 access_token 有效期2小时，过期后API返回认证失败
**处理策略**：
1. 自动检测token过期，用 Key/Secret 重新获取
2. 刷新成功则继续，用户无感知
3. 刷新失败才提示用户
**用户提示**（刷新失败时）：
```
⚠️ 【北森登录过期】北森招聘系统的访问凭证已过期，自动刷新失败
💡 建议：检查一下北森的 App Key 和 App Secret 是否正确，或者联系北森CSM确认接口权限
   你可以说"重新配置北森"来更新配置
```
#### 北森连接器未创建 / 权限未开通
**触发条件**：调用北森API返回"接口未授权"或"连接器不存在"
**处理策略**：引导用户检查北森后台配置
**用户提示**：
```
⚠️ 【北森权限未开通】北森OpenAPI接口还没开通
💡 建议：
   1. 登录北森管理后台 → 账户中心 → 管理后台 → 应用开发 >> OpenAPI连接器
   2. 确认已创建连接器并配置了IP白名单
   3. 联系北森CSM确认接口权限已开通
🔗 [北森配置指引](references/quick-start.md#方案b北森italent配置8分钟)
```
#### Moka "服务器异常"（阶段无候选人的特殊返回）
**触发条件**：Moka的 ehrApplications 接口，当查询的stage阶段没有候选人时，会返回"服务器异常"（这是Moka接口的特殊行为，不是真的服务器挂了）
**处理策略**：
1. 识别这种特殊情况（特定stage返回服务器异常）
2. 当作"该阶段暂无数据"处理，返回空列表
3. 不报错，不影响其他阶段和其他系统
**用户提示**（仅在调试模式下说明）：
```
ℹ️ Moka的[面试阶段]暂无候选人，已正常处理
（Moka接口在阶段无数据时会返回"服务器异常"，这是正常现象）
```
#### Moka Basic Auth 认证失败
**触发条件**：Client ID 或 Client Secret 错误
**处理策略**：提示用户检查凭证
**用户提示**：
```
⚠️ 【Moka认证失败】Moka的 Client ID 或 Client Secret 不正确
💡 建议：
   1. 去Moka开放平台确认应用的 Client ID 和 Client Secret
   2. 确认应用已申请了候选人数据接口权限
   3. 重新配置一下："帮我重新配置Moka"
🔗 [Moka配置指引](references/quick-start.md#方案cmoka配置8分钟)
```
#### 飞书 OAuth 授权过期
**触发条件**：用户身份模式下，user_access_token 过期且 refresh_token 也失效
**处理策略**：提示用户重新授权
**用户提示**：
```
⚠️ 【飞书授权过期】你的飞书招聘授权已过期，需要重新授权
💡 建议：点击链接重新授权一下，10秒钟搞定
🔗 [重新授权](https://open.feishu.cn/...)
```

### 10.2 多系统聚合异常处理
#### 部分系统连接失败（降级策略）
**触发条件**：多系统模式下，某一个或几个系统连接失败/认证失败/限流，但其他系统正常
**处理策略**：
1. 使用 Promise.allSettled 并行调用，某系统失败不影响其他
2. 正常系统的数据正常展示
3. 失败的系统在对应位置给出友好提示和重试入口
4. 整体不报错，用户还能用
**用户提示**（北森失败，飞书和Moka正常的示例）：
```
📊 今日待办汇总（飞书 + Moka）
━━━━━━━━━━━━━━━━━━━━
⚠️ 北森系统暂时连不上，已为你展示飞书和Moka的待办
   （你可以说"重试北森"来重新拉取）
[飞书] 待评估简历 5份 | 今日面试 2场 | 待写评估 1份
[Moka] 待评估简历 3份 | 今日面试 1场 | 待写评估 0份
...（正常展示飞书和Moka的待办详情）
```
#### 全部系统都失败
**触发条件**：所有配置的系统都连接失败
**处理策略**：整体报错，给出排查建议
**用户提示**：
```
⚠️ 【全部系统连接失败】飞书、北森、Moka都暂时连不上
💡 建议：
   1. 检查一下网络连接是否正常
   2. 确认各系统的凭证是否还有效
   3. 稍等一会儿再试试
   你也可以单独测试某个系统："从飞书拉一下待办"
```
#### 系统未配置但被引用
**触发条件**：用户说"从北森拉一下待办"，但北森还没配置
**处理策略**：引导用户配置
**用户提示**：
```
ℹ️ 你还没配置北森招聘系统哦
💡 建议：告诉我北森的租户ID、App Key、App Secret，我来帮你配置
   或者参考配置指南：[北森配置指引](references/quick-start.md#方案b北森italent配置8分钟)
```

### 10.3 各系统错误码映射表
| 系统 | 错误码/现象 | 含义 | 处理方式 |
|------|------------|------|----------|
| 飞书 | 99991668 | token过期 | 自动刷新，失败则提示重新授权 |
| 飞书 | 99991661 | token无效 | 提示重新授权 |
| 飞书 | 99991663 | 权限不足 | 提示缺少哪个scope，引导管理员开通 |
| 飞书 | 99991400 | 接口限流 | 自动退避重试 |
| 飞书 | 99991001 | 参数错误 | 记录日志，友好提示 |
| 北森 | 401/认证失败 | token过期或无效 | 自动刷新token，失败则提示检查配置 |
| 北森 | 接口未授权 | 连接器未创建或权限未开 | 引导去北森后台检查 |
| 北森 | 429/限流 | 请求太频繁 | 自动退避重试（限流100次/秒） |
| Moka | 服务器异常（特定stage） | 该阶段无候选人 | 当作空数据处理，不报错 |
| Moka | 401/Unauthorized | Client ID/Secret错误 | 提示检查凭证 |
| Moka | 403/Forbidden | 接口权限未申请 | 引导去Moka开放平台申请权限 |
| Moka | 429/Too Many Requests | 请求限流 | 自动退避重试 |
---
### 10.4 多系统异常处理总原则
1. **部分失败不影响整体**：一个系统挂了，其他系统照常工作
2. **失败有提示有入口**：失败的系统要明确告诉用户，并给重试方式
3. **自动重试不打扰**：网络问题、限流、token过期等自动重试，用户无感知最好
4. **特殊情况特殊处理**：比如Moka的"服务器异常"实际是无数据，不能真当错误
5. **并行调用不阻塞**：多系统用 allSettled 并行，不因为一个慢就全部等
